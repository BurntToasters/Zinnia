# Quick-extract recovery failure inventory

This inventory was written before changing production code. It covers the
quick-extract window (`extract-*` labels, `src/extract.html`,
`src/extract-window/*`, `src-tauri/src/launch/extract_window.rs`,
`launch/open_path.rs`, `launch/mod.rs`): choosing another destination after a
failed extraction, the failure layout, audit items M10 and M15, live theme
changes, and the launch re-export lint cleanup.

Coverage keys: `E2E-1`..`E2E-4` are the cases in
`e2e/specs/beta2-quick-extract-recovery.spec.js` (E2E-2 also covers a cancelled
picker); the backticked names are Rust unit tests in `launch/open_path.rs`
(`chosen_destination_tests`) and `launch/extract_window.rs`
(`choose_destination_tests`); `REVIEW` means no automated test can reach the
path and it was checked by reading the code.

## Choose another folder: backend command

1. A main-window or other non-extract caller reaches the picker and changes a
   binding. Mitigation: the first check in the command rejects any label that is
   not `extract-*` before the dialog opens. Coverage: `extract_window::choose_destination_tests::only_extract_window_labels_may_choose_a_destination`, the `grants choose_extract_destination to extract windows only` test in `tauri-capabilities.test.ts`.
2. The main window is granted the command through `default.json`. Coverage: the `grants choose_extract_destination to extract windows only` test in `tauri-capabilities.test.ts`
   (the default capability must not list `allow-choose-extract-destination`).
3. The extract window is not granted the command, so every press fails with
   a denied IPC. Coverage: the same `tauri-capabilities.test.ts` test and the import-transitive invoke scan (the extract capability lists it, and
   the import-transitive invoke scan finds it in `run-core.ts`).
4. The command is in the handler list but missing from `build.rs` COMMANDS, or
   the reverse. Coverage: existing "keeps generated command permissions aligned"
   test in `tauri-capabilities.test.ts`.
5. The generated permission or schema files are stale after the command is
   added. Coverage: existing schema alignment test; regenerated by `cargo build`.
6. The picker opens while an extraction for the same window is running. A
   webview click on Retry can race the modal picker. Mitigation: the busy check
   runs before the picker and again under the process lock before the rebind.
   Coverage: `choose_destination_tests::busy_slot_owned_by_this_window_blocks_a_choice` and `idle_slot_or_another_owner_does_not_block_a_choice` (pure predicate: owner match plus child, preparing or
   cancelling); the re-check after the picker shares that predicate. REVIEW for the
   race itself.
7. An idle slot owned by a different window must not block this window. Coverage: `choose_destination_tests::busy_slot_owned_by_this_window_blocks_a_choice` and `idle_slot_or_another_owner_does_not_block_a_choice`.
8. Cancelling the picker returns an error instead of `None`, so the frontend
   shows a false failure. Coverage: `chosen_destination_tests::cancelled_pick_returns_none_and_keeps_the_binding` (returns `Ok(None)`).
9. Cancelling the picker changes the binding. Coverage: `chosen_destination_tests::cancelled_pick_returns_none_and_keeps_the_binding`
   (the binding map is byte-for-byte equal before and after). E2E-2 also checks
   that the destination text is unchanged after a cancelled choice.
10. The chosen folder is a symbolic link or Windows junction, so the extraction
    would write outside the folder the user picked. Coverage: `chosen_destination_tests::symlink_or_junction_chosen_folder_is_rejected`
    (symlink on Unix, junction on Windows).
11. The chosen path is a file or does not exist. Coverage: `chosen_destination_tests::missing_chosen_folder_is_rejected` and `chosen_path_that_is_a_file_is_rejected`.
12. A file or link already occupies `<chosen>/<archive folder name>`, so
    extraction would collide with a non-directory. Coverage: `chosen_destination_tests::existing_file_at_the_derived_name_is_rejected`, `existing_link_at_the_derived_name_is_rejected`, and `existing_directory_at_the_derived_name_is_allowed_like_the_first_destination`.
    An existing directory at that name is allowed, matching the first destination's
    merge flow. Coverage: `chosen_destination_tests::existing_file_at_the_derived_name_is_rejected`, `existing_link_at_the_derived_name_is_rejected`, and `existing_directory_at_the_derived_name_is_allowed_like_the_first_destination` (positive case).
13. The derived folder name differs from the first destination's naming (the
    `.7z`, `.tar.gz`, and no-suffix `_extracted` rules). Coverage: `chosen_destination_tests::chosen_folder_derives_the_leaf_the_first_destination_used` and `archive_without_a_known_suffix_keeps_the_extracted_suffix_rule`
    (compares with `derive_extract_destination_path` for several archive names);
    E2E-2 checks the returned path ends in `writable/hello`.
14. The rebind changes the archive binding, or another window's binding.
    Coverage: `chosen_destination_tests::picked_folder_replaces_only_the_target_labels_destination` and `rejected_pick_leaves_the_binding_unchanged` (archive unchanged, other labels unchanged).
15. The rebind is not atomic: a reader sees the label missing between the remove and
    insert. Mitigation: one `get_mut` assignment under one lock. Coverage: `chosen_destination_tests::picked_folder_replaces_only_the_target_labels_destination` and `rejected_pick_leaves_the_binding_unchanged`
    (single map entry after the call). REVIEW for lock ordering: the process lock is taken
    before the binding lock and nothing takes them in the reverse order.
16. Rebinding a label that has no binding silently creates one. Coverage: `chosen_destination_tests::rebinding_a_label_without_a_binding_is_rejected`.
17. The returned path differs from the path stored in the binding, so the
    `-o` argument fails the bound-destination assert. Coverage: E2E-2 (extraction
    succeeds in the chosen folder, so `assert_extract_bound_destination` passed).
18. The returned path is canonicalized to a `\\?\` verbatim path, which 7-Zip may
    not accept. Mitigation: the stored path is `chosen.join(name)` from the picker,
    not the canonical form. Coverage: E2E-2 (7-Zip writes `writable/hello/hello.txt`).
19. The E2E picker hook is compiled into production builds. Mitigation: the hook
    lives under `#[cfg(feature = "e2e")]` and `e2e_session_active()`. REVIEW.
20. In an E2E session with no picker answer queued, the native dialog would block
    the test forever. Mitigation: the hook returns cancel when no answer file exists.
    Coverage: E2E-2 (the first press has no answer file and must keep the failure state).

## Failure state: layout, focus and actions

21. The Choose button appears for failures that do not allow recovery (for example
    archive validation errors). Mitigation: it is only shown when `showError` gets
    `offerRecovery`. Coverage: E2E-1 (the state is recoverable, so it shows).
22. A permission failure does not move focus to Choose. Coverage: E2E-1 (focus on
    `#choose-folder-btn`).
23. A non-permission recoverable failure moves focus to Choose instead of Retry.
    Coverage: REVIEW only. An E2E case needs a second failure type that reaches
    the recovery branch reliably, which is not available in the fixtures.
24. The permission message does not name the cause in plain words. Coverage: E2E-1
    (the detail matches "permission" or "read-only").
25. The failure message names the wrong cause: a read-only folder reports "cannot
    create" and maps to a generic hint. Coverage: E2E-1 asserts the permission text; if the
    backend text differs, E2E-1 fails and the mapping in `error-hints.ts` is the place to fix.
26. Choose or Retry stays visible during a new run. Mitigation: `hideRecoveryActions`
    hides both at the start of each run. Coverage: E2E-2 (the window reaches Done).
27. A double press starts two pickers or two runs. Mitigation: the button is disabled
    while its invoke is pending, and Retry checks `extractionRunning`. REVIEW.
28. A chosen folder that the backend rejects shows a false "Extraction failed" title.
    Mitigation: a choose error uses its own title and keeps both recovery buttons.
    REVIEW.
29. A successful choice does not retry. Coverage: E2E-2 (the file lands in the chosen folder).
30. The retry after a choice uses the old destination text. Coverage: E2E-2 (the
    `#extract-dest` text equals the new path and the file exists there).

## Layout (H6)

31. Any failure message pushes Retry and Close below the 320px window. Mitigation:
    the header and footer are fixed flex children; only `.extract-body` scrolls.
    Coverage: E2E-1 (footer boxes inside the viewport).
32. The titlebar scrolls away. Mitigation: `body` is a fixed-height flex column with
    `overflow: hidden`. Coverage: E2E-1 (`#titlebar` top is 0 and `scrollTop` is 0).
33. A long archive name pushes the window sideways. Coverage: E2E-3 (`scrollWidth`
    of the document and of `.extract-app` do not exceed `clientWidth`).
34. A long status line widens the body. Mitigation: `.extract-status` is
    `min-width: 0`, ellipsized, nowrap. Coverage: E2E-3 (status width stays within the
    container).
35. The window size changes. Mitigation: no change to `extract_window.rs` size. Coverage:
    E2E-1 (`innerWidth` 440, `innerHeight` 320).
36. Long unbroken text in the error detail widens the box. Mitigation:
    `overflow-wrap: anywhere` on the detail. Coverage: REVIEW.
37. The normal (non-error) layout changes. Coverage: E2E-2 (the window reaches Done
    and the open-destination and close buttons still show).

## M10: claim rejection

38. `get_extract_paths` rejects in the non-injected branch and leaves the window
    blank. Mitigation: the rejection is caught and shown through the failure state
    with Close focused. Coverage: REVIEW. The rejection cannot be forced from E2E
    (the only rejection is a poisoned lock).
39. The catch also swallows a real success. Mitigation: the `try` wraps only the
    await. REVIEW.
40. The injected branch behavior changes. It already catches with a warning. REVIEW.

## M15: live region

41. The visible status keeps `aria-live`, so every progress tick is announced.
    Mitigation: the status has no live attributes. Coverage: E2E-4 (the status element
    has no `aria-live` and the announcer is the only live region).
42. The announcer is missing or not a status region. Coverage: E2E-4 (the announcer
    exists with `role="status"` and records its text).
43. More than six announcements per run. Mitigation: at most one "Started", one per
    25% step (25, 50, 75, 100), and one terminal word. Coverage: E2E-4 (count is at most 6).
44. A percent that jumps past several steps announces each step. Mitigation: only the
    highest crossed step is announced. REVIEW.
45. Announcement text drifts from the main window's wording ("Started", "N% done",
    "Finished", "Failed", "Cancelled"). Coverage: E2E-4 (the recorded texts are checked
    against that set).

## Live theme

46. A system dark or light switch is ignored while the window is open. Mitigation:
    a `prefers-color-scheme` change listener re-applies the theme when the saved
    preference is "system". Coverage: REVIEW. The OS theme cannot be switched from WebDriver.
47. The listener re-applies a fixed light or dark preference. Mitigation: the handler
    returns early unless the preference is "system". REVIEW.
48. A Settings theme change while the window is open is not seen. There is no backend
    broadcast of settings changes (the main window applies its theme locally in
    `power-events/settings.ts`), so this is out of scope and is reported.

## Launch re-export lint cleanup (item 7)

49. A re-export is narrowed to the wrong platform and breaks macOS or Linux builds.
    Mitigation: each `#[cfg]` mirrors the cfg of the code that uses it. Coverage: REVIEW
    [unverified-os] on macOS and Linux.
50. A re-export used by `generate_handler!` is removed, breaking the handler list.
    Coverage: `cargo clippy --all-targets -- -D warnings` on Windows.
51. Clippy still fails on Windows because a re-export is unused only on Windows.
    Coverage: `cargo clippy --all-targets -- -D warnings`.

## E2E harness mechanics

52. The scenario runner launches with no arguments, so no quick-extract window exists.
    Mitigation: a file trigger (`e2e-open-extract.json` in `ZINNIA_E2E_WORK`), read by a
    watcher started from `mark_main_window_ready` under `#[cfg(feature = "e2e")]` and
    `e2e_session_active()`. It spawns a window through `spawn_extract_window`. Coverage:
    E2E-1 (the window appears and is switched to).
53. The trigger file is read while half written. Mitigation: the spec writes to a temp
    name and renames. The watcher ignores unreadable JSON and deletes the file.
    Coverage: E2E-1.
54. The trigger file is read twice, opening two windows. Mitigation: the watcher removes
    the file before spawning. Coverage: E2E-1 (the window count rises by one).
55. The read-only fixture is not read-only on this machine, or it is too broad. On
    Windows the fixture is a deny ACE for Everyone on the parent folder with the
    write-data and append-data rights only (`icacls /deny *S-1-1-0:(WD,AD)`). A deny
    of the generic `(W)` right also blocks SYNCHRONIZE, so even listing the folder
    fails with EPERM; the narrower deny was probed to keep listing working while
    creating a file or folder fails. On POSIX it is mode 0555, which root ignores.
    Mitigation: a POSIX precondition check fails the test loudly if the folder is
    still writable; the diagnostic outcome records whether the destination exists.
    Coverage: E2E-1.
56. The read-only ACE blocks cleanup of the profile. Mitigation: the `after` hook
    removes the deny ACE and restores mode 0755. Coverage: E2E cleanup (the profile is
    removed by the runner).
57. `browser.tauri.listWindows` returns the new window late. Mitigation: a bounded
    `waitUntil`. Coverage: E2E-1.
58. The extract window stays open after a case and leaks into the next. Mitigation: the
    spec closes each window through `close_extract_window` and switches back to `main`.
    Coverage: E2E-3 opens a second window after E2E-2 closes the first.
59. The single-instance plugin would forward `--extract` from a second process, but it is
    disabled in E2E sessions, so a second process cannot be used. Coverage: REVIEW (this is
    why the trigger file exists).
60. The fixture archive name is 200 characters, which exceeds MAX_PATH on Windows with a
    long work directory, so extraction may fail with a path error. The layout assertions
    still hold on the failure state. Coverage: E2E-3 checks layout only.
61. The live region is counted from a mutation observer installed after the run has
    already started, undercounting. Mitigation: the observer is installed before the
    Choose press that starts the run. Coverage: E2E-4.
62. A case depends on an earlier case's window or files. Mitigation: each case
    closes every extract window and removes the trigger, answer and destination
    leftovers in `beforeEach`, and each case opens its own window. A window is closed
    with a WebDriver click, the handle is switched back to `main`, and the tauri
    service label is reset before polling, because the service otherwise keeps the
    closed label and `listWindows` fails. Coverage: all four E2E cases run from a clean state.
